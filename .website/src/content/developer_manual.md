
# 开发者手册

站点使用 Vite 和原生 TypeScript 构建，源码位于 `.website/`，构建结果为可直接托管的静态文件。

## 本地开发

```bash
cd .website
pnpm install
pnpm run dev
```

提交前可运行完整检查：

```bash
pnpm run check
pnpm run build
```

## 内容维护

- 页面正文位于 `src/content/`，使用 Markdown 编写。
- 页面标题、简介和分组位于 `src/data/library.ts`。
- 结构简单的新增课程可由 `src/data/eie.ts` 生成；需要按学年或版本解释的课程应使用独立 Markdown 页面。
- 资料下载链接应指向仓库中的原始文件，并在提交前确认链接可以访问。
- 每份资料只能出现在一个课程页面中。移动或重命名文件时，必须同步更新资源清单和页面链接。

## 资料去重

资料收录前必须先检查内容，不以文件名是否相同作为判断依据。

1. 使用 SHA-256 查找内容完全相同的文件，只保留一份：

   ```bash
   find <课程目录> -type f -exec sha256sum {} + | sort | uniq -w64 -D
   ```

2. 同一试卷的 Word、PDF 等格式转换版本默认只保留一个入口，优先选择便于直接阅读的 PDF。只有可编辑源文件确有维护价值时，才同时保留，并在链接名称中标明“可编辑版”。
3. 压缩包不能与其全部散装内容同时收录。先使用 `7z l <压缩包>` 或 `unzip -l <压缩包>` 检查，只提取仓库缺少的资料；解包后没有独立内容的压缩包应删除。
4. 同一学年但内容不同的试卷可以并存，使用“版本 1”“版本 2”区分。不得仅凭年份相同将它们视为重复。
5. 删除重复项前需确认保留文件可正常打开，并同步删除资源清单与页面中的旧入口。

## 内容分层

课程资料按用途和学年组织，避免把课程名、年份和资料类型全部堆在同一级文件名中：

```text
课程名称/
├── 复习资料/
├── 章节题库/
│   ├── 第01章.pdf
│   └── 第02章.pdf
├── 历年试卷/
│   └── 2024-2025/
│       ├── A卷.pdf
│       └── A卷参考答案.pdf
├── 习题解答/
└── 课件/
```

- 课程目录使用站内统一名称，例如 `高数I`、`高数II`，不要为同一课程并存多个简称。
- 学年统一写成 `YYYY-YYYY`；只有确实无法确定学年时才使用单一年份。
- 文件名保留有检索价值的信息，如卷别、答案、评分标准和修订版本；删除 `(1)`、`x`、`NEW` 等无实际含义的下载痕迹。
- 目录已经表达课程和学年时，文件名使用 `A卷.pdf`、`A卷参考答案.pdf` 等短名称，避免重复课程全称。
- 题库按章节排序时使用补零编号，如 `第06章.pdf`，保证文件系统排序与教学顺序一致。
- README、课程设计等不在当前收录范围内的内容，不应因批量复制被带入资料目录。

## 索引检查

提交前逐项确认：

1. 新文件已加入课程页面，且只出现一次。
2. 页面链接解码后对应真实文件，文件更名后不存在旧路径。
3. 自动生成课程仍满足 `eieImportedPaths` 的完整性检查；人工分类课程仍需在 `courseConfigs` 中声明资源归属。
4. 页面按“复习资料、题库、历年试卷、答案或习题解答”的逻辑组织，不使用笼统的“新增补充资料”堆放不同年份。
5. `pnpm run check`、`pnpm run build` 和 `git diff --check` 均通过，并在浏览器中实际打开首页和受影响课程页面。

## 静态部署

`main` 分支中的站点文件发生变化后，GitHub Actions 会安装依赖、执行类型检查与构建，并将 `.website/dist` 发布到 GitHub Pages。

Vite 使用相对资源基址，因此站点既能部署在用户主页，也能部署在仓库子路径下。
